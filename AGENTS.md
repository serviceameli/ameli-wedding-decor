# Амели Декор — правила работы

Отвечай по-русски, простыми словами и без лишних рассуждений. Технические действия выполняй самостоятельно в рамках запроса.

Это существующая React/Vite-витрина `serviceameli/ameli-wedding-decor`, опубликованная на GitHub Pages. Сохраняй дизайн, корзину, комплектации и устойчивые ссылки разделов.

- Сначала проверь `git status --short --branch`, не включай чужие изменения.
- Node.js 22.23.0 и npm 10.x; используй `nvm use`, для чистой установки `npm ci`.
- Компания всегда «Амели декор», ID **30**. Не делай ID настраиваемым и не определяй компанию по hostname.
- API `https://api.ameli-dekor.frents.ru/client-company`; подтверждай маршруты по Swagger и существующим сервисам.
- `npm run catalog:sync` загружает публичные данные при сборке. Прямые browser-запросы с GitHub Pages сейчас не разрешены CORS. Не ослабляй CORS и авторизацию.
- Комплектации связываются по данным API. Не объединяй товары по похожим названиям, не выдумывай цены, состав, срок аренды или наличие.
- Выгрузка содержит только явно выбранные публичные поля. Не сохраняй полные ответы API, служебные поля, заказы, cookies, токены и персональные данные.
- `.env` и `work/` не публикуются. Приватный проект программиста в `work/ameli-dekor-site` имеет свои инструкции; не копируй его целиком в открытый репозиторий.
- `data/fixtures.ts` — старые данные для тестов. Рабочий источник — `data/generated/catalog.json`.
- Для API-изменений: `npm run doctor`, тесты импортера. Перед публикацией: `npm test`, `npm run lint`, `npm run build`. Для интерфейса проверь браузер, мобильную ширину и затронутую интеракцию.
- Push в `main` запускает реальную публикацию GitHub Pages. Делай commit/push только в рамках разрешённой пользователем работы. После публикации проверь workflow и SHA в `/catalog-status.json`.
- Не отправляй реальные заявки и не изменяй заказы, профили и платежи без отдельного запроса. Корзина пока сохраняет подборку без бронирования.

Подробности, повторный запуск и откат: `README.md`, `docs/INTEGRATION.md`.
