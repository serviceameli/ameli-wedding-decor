# Подключение к основному арендному движку

Это независимый frontend-прототип. Публичные данные основного сайта использованы как локальный снимок. Серверный движок, наличие на дату и оформление реальных заказов не подключены.

## Каталог и варианты

`data/types.ts` задаёт Product, ProductVariant и CompositionItem. `data/catalog.ts` содержит заменяемый `CatalogProvider.listProducts(signal)`; текущая реализация читает `data/fixtures.ts`.

Для подключения модуля базы данных возвращайте массив товаров. У каждого товара нужны стабильный id, category, name, image, description, defaultVariantId и непустой variants. У каждого варианта — собственный стабильный id, label, price, unit, rentalDays, image, description, composition и sourceUrl. Состав содержит id, name, quantity, при наличии image и sourceUrl. Внешние HTTPS-изображения поддерживаются.

Не храните цену и состав только на родительском товаре: интерфейс и корзина используют выбранный вариант. Не определяйте комплектацию по названию или умножением базовой цены. Количество и набор вариантов произвольны; три уровня у столов и другие варианты у церемоний приходят из данных.

`data/categories.ts` управляет деревом каталога. Для нового раздела добавьте строку с уникальными id и slug; parentId ссылается на родительский раздел, отсутствие parentId делает узел корневым. Глубина вложенности не ограничена фиксированными уровнями. В товарах укажите category — стабильный id категории. Родительские страницы и счётчики автоматически включают товары всех потомков. Старые slug шести категорий готовых решений сохранены. `scripts/build-pages.mjs` создаёт HTML для каждой категории и каждого родительского товара. Вариант передаётся параметром `?variant=ID`. При подключении базы генератор должен получать актуальные товары во время сборки либо маршруты нужно передать основному серверному движку.

## Корзина

`lib/cart.ts`: строка — productId, variantId и quantity. Цена и состав вычисляются по текущему варианту, не берутся из сохранённых пользовательских значений. Количества ограничены 200 единицами в демоверсии; это не информация о наличии. Старые строки без variantId мигрируют на defaultVariantId; явно неизвестные варианты удаляются.

В localStorage хранятся только ID, количества, избранное и выбранные варианты. Контактные данные формы находятся в памяти вкладки и попадают в текстовый файл только по нажатию кнопки скачивания.

Перед настоящим заказом сервер заново проверяет вариант, цену, наличие, состав, период аренды, залог и дополнительные услуги. Идентификатор варианта необходимо передавать в заказ; productId без variantId недостаточен.

## Заявка и размещение

В `app/page.tsx` шаг review — только предпросмотр. Подключите серверный OrderProvider/createInquiry с проверкой данных, состояниями отправки и ошибки и подтверждением от сервера. Только после успешного ответа можно показывать номер заявки и факт отправки.

Для настоящего запуска замените демонстрационные тексты и согласие, добавьте утверждённые условия и политику обработки данных. После приёмки обновите метаданные и снимите noindex.

`npm run build` создаёт dist с относительными URL для GitHub Pages и другого статического хостинга. Для основного движка можно сохранить React-витрину либо перенести компоненты и стили в его шаблоны.

## Отдельные предметы и расширение

Для отдельного товара передавайте `kind: 'item'`, например стула или бокала. Для готового решения — `kind: 'solution'`; отсутствие kind в старых данных считается готовым решением. У отдельного товара также есть variants (хотя бы один), свой unit и цена, например «за 1 стул». Если состава нет, возвращайте пустой composition: интерфейс не показывает пустую секцию состава. Корзина объединяет любые виды товаров по паре productId/variantId.

Корневые разделы: ready-solutions, dishes, seating, furniture, textiles, decor. Это стартовая структура, а не закрытый список. `lib/catalog-tree.ts` обрабатывает произвольные родительские связи, проверяет уникальность маршрутов, отсутствующих родителей и циклы. `scripts/build-pages.mjs` проверяет дерево и создаёт все страницы. Новые товарные разделы сейчас пустые: показаны работающие страницы и дочерние категории, реальные позиции не выдуманы.

После добавления категории и товаров выполните `npm test` и `npm run build`, затем опубликуйте dist. На статическом GitHub Pages новая категория требует пересборки. При переносе на основной движок модуль должен отдавать не только товары, но и соответствующее дерево категорий; построение маршрутов и навигации использует один источник. Административный редактор категорий в прототип не входит.
