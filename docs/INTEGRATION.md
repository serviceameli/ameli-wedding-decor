# Подключение каталога компании №30

Витрина — статический React-сайт на GitHub Pages. API: `https://api.ameli-dekor.frents.ru/client-company`. [Swagger](https://api.ameli-dekor.frents.ru/client-company/docs). [Исходный каталог](https://ameli-dekor.frents.ru).

## Данные при сборке

На 12 сентября 2026 API не возвращает `Access-Control-Allow-Origin` для `https://serviceameli.github.io`. GitHub Pages не исполняет серверный Nuxt-код. Поэтому браузер получает публичную выгрузку вместе с сайтом; GitHub Actions запрашивает API перед публикацией. CORS, cookies и авторизация исходного сервиса не меняются. `localhost:3004` нужен только для отдельного проекта программиста.

Компания фиксирована: ID 30, имя «Амели декор». Хост браузера, query-параметры и окружение не меняют Company ID. `.env` содержит только необязательное переопределение HTTPS API и не попадает в Git.

## Источники

Только документированные GET-запросы:

- `/api/v1/company/30/` — проверка компании.
- `/api/v1/categories-site/30/?choice_category=parent` — дерево категорий.
- `/api/v1/categories-site/slug/vysokie-stojki/30/` — диагностическая пустая категория.
- `/api/v1/decor/` — все страницы с `company_id=30&st=30`.
- `/api/v1/decor/{id}/` — полные данные решений и связанных комплектаций, с проверкой ID и компании.

API ограничивает страницу 150 товарами. При подключении счётчик сообщал 1030, но все страницы возвращали 1027 уникальных товаров. Такое расхождение принимается только после повторной полной загрузки с другим размером страницы и сравнения всех ID. Точная причина расхождения требует проверки backend программистом. Дубли, меняющаяся пагинация, ошибки и несовпадение повторной загрузки останавливают публикацию.

## Категории и комплектации

Явные соответствия категорий сохраняют прежние адреса; адреса API добавлены как альтернативные маршруты. Множественные категории учитываются в фильтрах, общий родитель считает товар один раз.

ID товара: `ameli-{id}`, ID варианта: ID изделия из API. Комплектации появляются только по связи `decors_repaint` с `is_alternative=true` и `hide_in_catalog=true`. Их составы и цены загружаются отдельно. Публичные цветовые альтернативы остаются отдельными карточками. Похожие названия не являются основанием для объединения.

В выгрузку попадают только публичные поля витрины. Полные ответы API не сохраняются: служебные себестоимости, бронирования, комментарии и прочие поля отбрасываются. Для изображений разрешены только HTTPS-хосты `cdn.frents.ru` и `storage.yandexcloud.net`; отсутствующие фото заменяются нейтральной заглушкой. Описания выводятся текстом, без исполнения HTML.

Срок аренды показывается только при явном `rental_period_days` из API. Иначе — «период аренды уточняется». Складское количество не выдаётся за наличие на дату. Раздел «Высокие стойки» остаётся пустым согласно API.

## Корзина и заявки

Корзина хранит ID товара, ID варианта и количество. Цена берётся из текущей выгрузки. Старые неизвестные ID не преобразуются в новые товары по названию; прежние демо-фикстуры используются только в тестах.

Контакты посетителя находятся в памяти вкладки. Файл создаётся только по кнопке «Скачать подборку». Заказы, даты наличия, платежи и авторизация требуют отдельного подключения. Автоматическая отправка заявок не выполняется.

## Публикация и откат

Цель: `serviceameli/ameli-wedding-decor`, GitHub Pages, `https://serviceameli.github.io/ameli-wedding-decor/`, ветка `main`. Дополнительные API-секреты не нужны. Используются стандартные ограниченные разрешения GitHub Pages. `/catalog-status.json` показывает компанию, число карточек, время и SHA публикации.

Неуспешная сборка сохраняет предыдущий сайт. Откат: отменить коммит в `main` и повторить публикацию либо выбрать сохранённую ветку `gh-pages`, `/` в Settings → Pages.
